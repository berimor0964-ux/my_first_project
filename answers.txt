1. В Git есть три основные области: рабочая папка, индекс и репозиторий.
Рабочая папка - файлы проекта с которыми непосредственно ведётся работа
Индекс - промежуточная область, куда с помощью команды git add добавляются изменения
Репозиторий - место где Git хранит историю коммитов и сохранённые версии проекта.
2. git add - добавляет изменнеия из рабочей папки в индекс, готовит к комиту
git commit - сохраняет подготовленные в индексе изменения в локальном репозитории.
git push - отправляет созданные локальные комиты в удалённый репозиторий.
3. Информативные сообщения к комитам требуются ради банального понимания. Чем проще понять сообщение в коммите тем легче сделать изменения или найти нужные 
4. git add имя_файла - добавляет в индекс только указанный файл
gir add . добавляет все обнаруженные в директории изменения
первое лучше использовать когда нужно добавить конкретный файл, а второй случай когда нужно добавить всё.
5. git status  показывает текущее состояние репозитория
если файл был изменён и не добавлен в индекс он отображается как изменённый
после git add файл попадёт в список изменений подготовленных к комиту
после комита рабочая папка и индекс обычно становятся чистыми если все изменнения сохранены
6. Команда git remote add origin URL связывает локальный репозиторий с удалённым по URL.
origin - это стандартное имя обозначающее основной удалённый репозиторий
7.флаг -u устанавливает связь между локальной веткой main и удалённой веткой main
после этого Git запомнит связь и будет использовать её в дальнейшем.
8. Ветка по умолчанию - это основная ветка репозитория у меня ветка main
9. Историю комитов можно посмотреть командой git log
Она показывает индефикатор комита автора дату создания и сообщение комита
10. Если изменить файл н оне выполнить git add изменения останутся только в рабочей папке и не попадут в индекс
при комите эти изменения не будут включены в новый комит.
